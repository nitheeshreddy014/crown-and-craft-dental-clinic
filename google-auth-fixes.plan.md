# Google Auth Fixes — Crown & Craft Dental Clinic

## Overview

Three targeted fixes for the Google OAuth login flow. No redesign — just the exact broken parts.

**Root problems found in code:**
1. `/api/login` in `main.py` has no `auth_provider` check — Google-only users get a silent "Invalid credentials" when trying email/password login
2. `google_callback` in `main.py` always redirects to `/my-appointments` — no first-time setup flow
3. `my_appointments.html` has no mechanism to collect phone number from Google users (Google API doesn't return phone)

## Fix Details

### Fix 1 — `/api/login` in `main.py`
**Problem:** If a Google-only user (has `auth_provider="google"` and a random unknown password_hash) tries to login with email+password, they get `"Invalid email/username or password"` — no hint to use Google.

**Solution:** Before the `_verify_pw` check, inspect `auth_provider`:
```python
user = get_user_by_email(uname)
if user and user.get("auth_provider") == "google":
    return JSONResponse(status_code=401, content={
        "success": False,
        "message": "This account uses Google Sign-In. Please click 'Continue with Google' to log in."
    })
if user and _verify_pw(form.password, user["password_hash"]):
    # ... existing login success
```

---

### Fix 2 — `google_callback` in `main.py`
**Problem:** After Google creates a new user, they're sent straight to `/my-appointments` with an empty phone field and no prompt.

**Solution:** After login, check if phone is empty → redirect with `?setup=1`:
```python
# After getting user from DB
is_new_google_user = not user.get("phone")
redirect_url = "/my-appointments?setup=1" if is_new_google_user else "/my-appointments"
resp = RedirectResponse(url=redirect_url, status_code=302)
```

---

### Fix 3 — `templates/my_appointments.html`
**Problem:** No UI to collect phone from Google users. Profile tab exists but isn't surfaced automatically.

**Solution:** Add a modal that auto-opens when `?setup=1` is in the URL.

Modal behaviour:
- Opens automatically on page load if `?setup=1` present
- Has phone number input + Save button
- "Skip for now" closes it without saving
- On save → calls existing `/api/profile` PUT endpoint
- After save or skip → removes `?setup=1` from URL using `history.replaceState`
- Does NOT show again once phone is set (redirect logic in Fix 2 handles this)
